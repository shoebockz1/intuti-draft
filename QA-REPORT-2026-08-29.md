### 1. Keeping on the jump pick leaks the seal exemption — CRITICAL

When the 5th-place winner reaches their jump pick, the pick panel **defaults to the "Own player" tab** and offers 19 Keep buttons — it literally says "Use Keep buttons below". Clicking Keep is the most natural action available, and it consumes the jump pick. But `keepOwn()` never clears `fifthJumpPending` or sets `fifthJumpUsed` — only `draftUnprotected()` does.

The exemption then floats and re-attaches to the winner's **next** pick.

**Reproduction** (confirmed live on production *and* against the real engine):

1. Load 2025 rosters → load 2026 draft order → Start draft
2. Jason keeps. Phil drafts unprotected. Tee drafts unprotected → jump triggers, Mark Jr on the clock
3. On the jump pick click **Keep**. Jump row records `type:"kept"`, but `fifthJumpPending` stays `true`
4. Advance to Mark Jr's natural R1 slot 7 turn — he is still badged "Jump pick"
5. Draft any unprotected player

```
Observed:  Mark Jr sealBroken false | unprotCount 2
Expected:  Mark Jr sealBroken true  | unprotCount 3
natural R1S7 pick recorded as type:"fifth-jump", isFifthJump:false
UI told him: "5th place jump — seal stays intact after this pick."
```

He also still gets the Round 18 skip. Net effect: an extra pick, **and** a free unprotected pick, **and** an intact seal — with his whole roster staying sealed away from the other nine owners.

### 2. Round 18 balancing skip never enforced — CRITICAL

`isSkipped` is set by `markFinalRoundSkip()` and read by `Board.tsx` to paint a grey "skip" cell — that is the **only** thing it is ever used for. Nothing advances `cur` past a skipped pick, so the draft still puts the 5th-place winner on the clock there and waits.

There is no way to advance without entering a player, so the commissioner must either fill the slot or abandon the last six picks.

**Reproduction** — full 181-pick draft driven through the real server engine, taking the jump correctly so finding 1 was not in play:

```
rows marked isSkipped:   R18 S4  owner=Mark Jr
draft put someone on the clock on a skipped row: 1 (pick index 174)
players per owner: Mark Jr 19, all others 18
```

The board shows the cell as "skip" while the on-clock bar demands a pick for it — visually self-contradictory as well as wrong. The identical gap exists in `intuti-draft-prototype.html` (lines 690, 871, 880), so it was inherited, not lost in translation.

### 3. Pending-jump state wording is misleading — MAJOR

This is the intermediate state the brief flagged as never verified. **The wording is misleading.** `getFifthJumpInfo()` only distinguishes "a jump pick has a player" from "it doesn't" — it has no notion of `fifthJumpPending` — so the armed state renders identically to not-yet-triggered.

On `/` and `/boardonly` alike the on-clock bar says `Mark Jr · Pick 4 · Round 1` with the counter at `2/3`, while the line directly beneath says the jump *will* happen once the 2nd unprotected pick is made. It already has.

```
Observed:  "not yet triggered — Mark Jr jumps the order once the 2nd unprotected pick is made"
Expected:  something like "on the clock now — Mark Jr is taking the jump pick"
```

Both surfaces agree with each other exactly, as designed — they share the helper, so one fix covers both.

### 4. Touch targets revert to desktop size, 641–1080px — MAJOR

The layout breakpoint and the touch breakpoint disagree. `draft.css` collapses to the stacked single-column layout at `max-width: 1080px`, but every touch-target and font-size rule in `theme.css` is gated at `max-width: 640px`. In the 641–1080px band you get the mobile layout with untouched desktop controls.

This is not just tablets. **A 375×812 phone rotated to landscape is 812px wide** — and `/boardonly` actively tells people to rotate. Rotate, tap back to `/` to pick, and the Keep button is 42×19px: the exact dimension the CSS comment says was fixed.

```
viewport  640px →  Keep 44px · select 16px   PASS
viewport  641px →  Keep 19px · select 12px   FAIL
viewport  812px →  Keep 19px · select 12px   FAIL  (phone landscape)
viewport  768px →  Keep 19px · select 12px   FAIL  (iPad portrait)
viewport 1024px →  Keep 19px · select 12px   FAIL  (iPad landscape)
```

At 812×375 on `/`: 30 controls under 40px. The 12px select also crosses iOS Safari's focus-zoom threshold. Note this is a **stylesheet gap, not** the inline `style={{fontSize}}` bug from before — there are no inline font sizes on any focusable on any page.

### 5. State payload grows unbounded — MODERATE

Every pick pushes a deep clone of the entire state onto `history`, and `GET /api/draft/state` returns all of it. Each polling tab re-downloads it every 2 seconds.

```
Measured at pick 77 of 181:  2.00 MB per poll (history 2,060,486 bytes = 98.7%)
Actual useful state:         27 KB
```

Projecting linearly, ~5 MB by the final pick. Visibility gating keeps it to about one tab per person, but ten owners at 5 MB every 2s is ~25 MB/s of egress from a free-tier instance late in the draft — exactly when it matters most. The same payload is written to Redis on every pick.

**Cheap fix:** omit `history` from the `/state` response — no client reads it, undo is a server-side POST.

### 6. Commissioner login lost on restart — MODERATE

`express-session` is configured with no `store`, so it uses the default `MemoryStore` — per-process, gone on restart. This happened during testing: the session went from `isCommissioner: true` to `false` without logging out.

A Render free-tier spin-down, redeploy or crash silently logs the commissioner out, and **Undo stops working at the moment it's most likely to be needed** until the passcode is re-entered. `MemoryStore` is also documented as leaking memory and not for production.

Good news from the same event: the draft survived intact — 78 picks, all owners, all flags. **Redis persistence works**, which clears §8's restart-mid-draft case.

### 7. Keep endpoint has no seal check — LOW

`POST /api/draft/pick/keep` applies `protected[protIdx].used = true` with no rule validation. Confirmed it accepting a keep for Vince *after* his seal had broken, recording `type:"kept"`. Per §2 a broken-seal owner can no longer keep.

Not reachable by normal clicking — `ProtectedPanel` hides Keep buttons once a seal breaks. Flagged as defence-in-depth. **Distinct from the optimistic-concurrency guard you declined** — this is a missing rule check, not a stale-view race.

### 8. Two panels on `/` disagree — LOW

The left sidebar hardcodes `"free"` for every unused player on a broken-seal roster (the documented TODO). The right sidebar and `/rosters` both use `TeamRosterView`, which resolves the real status. When the on-clock owner has a broken seal and one of their players is already taken, the left panel says "free" while the right says "drafted".

### 9. `/players` Draft buttons have no confirmation — LOW

A single click on any of ~1,100 Draft buttons lands a live pick for whoever is on the clock — no confirm, no undo affordance on that page. Easy to misfire on a phone in a scrolling list, on the page used for browsing rather than picking.

## What I could not verify

- **A real physical phone.** All mobile testing was viewport emulation at 375×812, 812×375, 768×1024 and 1024×768, reloading after each resize. Real iOS Safari focus-zoom and real touch accuracy remain unconfirmed.
- **Genuine ctrl / cmd / middle-click opening real tabs.** The harness can't synthesize a native new-tab gesture. `AppLink` returns early on modified clicks and non-left buttons without calling `preventDefault`, and a ctrl-click left the page unchanged — so the native path is intact, but click it once by hand to be sure.
- **Re-sync on a real tab re-focus.** The pane never flips a background tab back to `visible`, so `visibilitychange` was dispatched directly on a genuinely hidden, genuinely stale tab. The 0ms re-sync and 0-calls-while-hidden results are real; only the final focus gesture was simulated.
- **Rate limiting.** Scripted `curl` against the API tripped a Cloudflare managed challenge (HTTP 429) partway through. I did not attempt to work around it and switched to the browser session, which was unaffected. Fast automated traffic to this host gets challenged.

Also worth noting: I never saw or typed the commissioner passcode. The `/admin` session was already authenticated in the browser and I took it over.
